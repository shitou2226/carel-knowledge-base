# CAREL 仿真与在线调试

## 本文解决的问题

区分编译、Windows 仿真与物理控制器在线运行，并知道应检查哪些结果。

## 官方说明及步骤

应用仿真由 Windows 上的虚拟机执行资源代码；物理输入输出被忽略。编译器为仿真与在线运行生成不同代码，运行仿真前要先构建工程。[0205_应用仿真.md](../90-%E5%8E%9F%E5%A7%8B%E8%B5%84%E6%96%99/%E5%B8%AE%E5%8A%A9%E8%AF%91%E6%96%87/0205_%E5%BA%94%E7%94%A8%E4%BB%BF%E7%9C%9F.md)

官方入门流程：选 Simulation → Start Debugging → 在程序中观察调试信息 → 变量 Add to Spy List → 结束时 Stop Debugging。[0201_从基础应用开始创建工程.md](../90-%E5%8E%9F%E5%A7%8B%E8%B5%84%E6%96%99/%E5%B8%AE%E5%8A%A9%E8%AF%91%E6%96%87/0201_%E4%BB%8E%E5%9F%BA%E7%A1%80%E5%BA%94%E7%94%A8%E5%BC%80%E5%A7%8B%E5%88%9B%E5%BB%BA%E5%B7%A5%E7%A8%8B.md)

视频的时间定位保留在 [仿真调试](../09-%E8%A7%86%E9%A2%91%E8%AF%BE%E7%A8%8B%E7%AC%94%E8%AE%B0/0303_%E4%BB%BF%E7%9C%9F%E8%B0%83%E8%AF%95.md)，其机器字幕用于返回录屏，不作为参数依据。

## MCP 检查顺序

先读状态和当前工程；在用户确认后才改变工程或仿真状态。编译后轮询 build_status 到 vsBuildStateDone，再读最终诊断。仿真启动请求不等于 Running，变量值须附 Good quality 和时间戳。

## 常见错误

将模拟输出当作物理端子有电；把编译成功当作联锁已验证；编译进行中使用上次错误列表；运行中直接编辑/构建。

## 尚未核实

本轮未启动或写入仿真，也未连接物理设备；在线下载与 I/O 行为仍待目标设备验证。
